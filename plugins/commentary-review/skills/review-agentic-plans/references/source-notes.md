# Source notes

Last reviewed: 2026-08-23

- Google, *Software Engineering at Google — Documentation*: design documents should state goals, strategy, key decisions, alternatives, tradeoffs, and cross-cutting concerns. https://abseil.io/resources/swe-book/html/ch10.html
- Google Engineering Practices, *What to look for in a code review*: review overall design and user-facing functionality before local details; resist unnecessary complexity. https://google.github.io/eng-practices/review/reviewer/looking-for.html
- Anthropic, *Building effective agents*: use environment feedback, human checkpoints, stopping conditions, and evaluator–optimizer loops when criteria are clear. https://www.anthropic.com/engineering/building-effective-agents
- OpenAI, *A practical guide to building agents*: escalate after bounded failures and before high-risk actions. https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/
- Microsoft Research, *Human oversight of agentic systems in practice*: oversight includes a priori control, co-planning, real-time monitoring, and post hoc review. https://www.microsoft.com/en-us/research/publication/human-oversight-of-agentic-systems-in-practice-examining-the-oversight-work-challenges-and-heuristics-of-developers-using-software-agents/
