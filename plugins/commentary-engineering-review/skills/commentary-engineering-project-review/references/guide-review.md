# Review guides, changes and readiness

Use a short purpose, named version and ordered contents to orient the reader. The rendered guide is primary; preserve independent Document/Changes and Preview/Raw choices. Keep questions and technical context in their contained panels.

For "Since your last visit", use the authorized viewer/workspace's immutable visit receipt and exact comparison endpoints. Resume follows the latest accessible composition at the last item; it is not the saved comparison baseline. If an endpoint is unavailable, report that outcome rather than substituting latest or All PR changes. Bound change pages and retain publication order even across force pushes. Report material impact and exact acceptance currency separately; an unchanged-looking document does not transfer an old Decision to a new revision.

Questions retain the original guide revision, target revision/digest and file/anchor or source selection. New investigations default shared; legacy v1 requests stay private. Each reader/reply needs current guide and original-source access. Do not copy private context into a shared answer or retarget a question to the current guide. Assigned-agent responses use the scoped Interaction message operation; requesting an investigation uses the eligible human path. For response mechanics use commentary-project-feedback-loop when installed, or discover the Interaction message schema before proceeding.

Read settings and the exact revision's gate before preparation or downstream work. Polls and Consensus are independent and start off on new reviews. Guide discussion/settings are independent of linked reviews; package settings are shared with the backing draft. Never reset settings when opening a guide. Honor prepareChanges and continueDownstream separately. Ordinary conversation, proposal decisions, application claims and exact human acceptance remain distinct. Uploading a correction does not clear blockers or waive sign-off. Only an eligible human can set or remove human requirements.

Acceptance targets select one deliverable or an explicit Session subset and bind supporting requirement/evidence revisions. Re-read the resulting manifest before requesting a Decision. Keep all unrelated composition targets during a revision, and do not use a poll, resolved thread, Tracker completion or reported application as proof of human acceptance.
