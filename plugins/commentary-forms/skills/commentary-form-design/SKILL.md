# Commentary Form Design

This compatibility skill preserves the existing skill id while routing work into the separated technical and practice skills.

- Use `commentary-form-rendering` for Markdown or MDX embeds, declarative static HTML bindings, Forms SDK integration, custom renderers, sandboxing, and Live Preview review handoff.
- Use `design-effective-forms` for question wording, response choices, information flow, validation experience, accessibility, visual hierarchy, mobile behavior, and adaptive personalization decisions.
- Use both when the user wants a thoughtfully designed form implemented as a rich Commentary renderer: design the experience first, then implement the renderer.

Do not duplicate contract-authoring mechanics here; use `commentary-form-creation`. Do not duplicate result retrieval; use `commentary-form-results`.
