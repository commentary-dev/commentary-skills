# Project Feedback Loop example

Read the [portable workflow source](https://github.com/commentary-dev/commentary-skills/tree/main/examples/projects) for the feedback fixture and CLI-capable/MCP-only adapters. Version 0.1.0 is tested with Projects Contract v1, CLI 0.2.0 and Agent SDK 0.2.0. The fixture validates requests and recovery; it is not live provider, browser isolation or genuine human acceptance evidence.

The executable fixtures preserve exact versions and report awaiting_human. Use the deployed schemas for real identifiers and upload limits.

## Exact workflow

Read current Package and Session, native revision comments and typed Interaction feedback. Publish addressed bytes through the upload flow, then revise targets preserving unrelated resources. Get the new Session before acceptance_request and use its exact revision/fingerprints and current ETag. Refuse self-approval and return awaiting_human. Existing commentary-submit-revision handles Interaction proposal provenance; package revision publication alone does not revise an Interaction.
