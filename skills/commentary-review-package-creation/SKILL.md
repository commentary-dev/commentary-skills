# Commentary Review Package Creation

Prepare a rendered document walkthrough with a clear entry page, stable page ids, navigation, related Resources and disclosed limitations. Preserve semantic anchors and app-native threads. Markdown/MDX/HTML are sanitized; MDX expressions and imports are not a build mechanism. Static documents and executable bundles are different trust tiers.

When filesystem/terminal capability exists, use the dedicated package CLI collector for an explicitly selected directory. Validate or dry-run, review excluded secrets/symlinks/path and MIME diagnostics, then publish with a stable retry key. Sync after meaningful edits; watch only when requested and within a foreground budget. Do not widen ordinary Draft collectors or execute customer scripts.

MCP-only operation uses bounded literal manifest/assets via discovered prepare/chunk/status/finalize/publish operations. If uploads are unavailable, return the prepared portable bundle with an unsupported-capability diagnostic. Confirm byte/hash receipts and immutable revision readiness before calling publication complete. Resume interrupted transfers from server status, preserving the original bytes, offsets and keys.

Read [references/operating-contracts.md](references/operating-contracts.md) before transport selection or recovery. Use [references/worked-example.md](references/worked-example.md) for the validated package workflow and its limits.
