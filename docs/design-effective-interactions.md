# Design Effective Interactions

Use this practice skill to make human requests clear, proportionate, and easy to answer. Install `design-effective-interactions` directly or use the `commentary-inbox` plugin.

Canonical instructions: [SKILL.md](../skills/design-effective-interactions/SKILL.md).

## Choose the right request

Use ordinary chat for an immediate question, and a durable Interaction when the person needs time or a persistent decision record. Ask for an answer when information is missing, a choice when selecting alternatives, an acknowledgment when receipt matters, and approval when authorizing an exact consequence.

Reply discusses the current task. Teach this agent is future-facing guidance. Neither automatically constitutes the requested Decision, and receipt of guidance does not prove learning or application.

A full Review is appropriate when the artifact needs sustained discussion. Use the human-confirmed canonical handoff rather than an invented agent escalation route.

## Make the consequence legible

State what needs attention, why it matters, the meaningful options, and what happens after each option. Keep independent actions separate and use concise summaries with canonical artifact links. Preserve alternatives and uncertainty rather than pushing toward approval.

Match friction to consequence. Bind requested approval to the current immutable action payload; a label or decorative confirmation phrase cannot provide enforcement. Do not imply that Commentary executed or verified an external operation.

Use supported bounded content blocks and accessible wording. Discover the actual server contract before assuming images, fields, or actions are supported. Pair this practice skill with the relevant technical Inbox skill for creation and continuation.
